# 0.0.3 — the harness, part 2 — PLANNED

> **Scope:** the remaining stages, the self-check that proves the harness can
> fail, and the tree checks that diff the library against the documents
> describing it. **The self-check is the load-bearing half**: a suite that only
> ever agrees with what it is handed reports green while checking nothing.

## 1. Decisions taken at planning

- **P-18 — the exact-code rule from the start** (D-237). On the error channel,
  the SET of codes a rejection test reports must EQUAL the set its expectations
  name. The compiler ran the weaker subset rule for six cycles and found, when
  it tightened, that 17 of 131 files were reporting something nobody had
  asserted. Starting strict costs nothing; loosening later is impossible.
- **P-19 — a skipped stage prints a line saying it was skipped and why**
  (`specs/TESTING.md` V-2). Silence is how a suite becomes green on a machine
  where it ran nothing — and this library has a stage (`network`) that is
  legitimately skipped almost everywhere, which makes the rule matter more here
  than it did for `ntui`.
- **P-20 — `loopback` and `network` are different stages** (`SK-030`), and
  `loopback` is **not** skippable. If loopback does not work the machine is
  broken and a green run would be a lie.
- **P-21 — the three enforcement checks are written now, before there is
  anything to enforce.** `check_msg_nosignal`, `check_no_floor_write` and
  `check_no_raw_setsockopt` all have empty inputs today and go live the day 0.2
  writes the first send site. Writing them first is what stops the *first* call
  site being the exception that gets grandfathered.
- **P-22 — the tree checks run on every full invocation**, including the ones
  with nothing to check. `check_struct_sizes` over an empty set is the right
  answer and is what makes the check exist on the day the first layout lands.

## 2. The stages added

| Stage | Tool | Passes when |
|---|---|---|
| `parse` | the compiler's `tools/parse_check` | every `.npk` in the tree accepted with no diagnostic |
| `accept` | the compiler's `tools/check` | accepted in silence |
| `check` | the compiler's `tools/check` | refused with **exactly** the expected codes |
| `loopback` | the built program | as `program`, over `socketpair` / `127.0.0.1` / `[::1]`; **never skipped** |
| `network` | the built program | as `program`, needs an outside host; **skipped loudly** |

The three tools come from the compiler's tree, built once per run from the
pinned checkout.

## 3. The self-check — the seven cases

`harness/selfcheck.py` constructs each case, runs the harness against it, and
requires a **failure**:

1. a `program` case whose `expect-exit` is wrong by one
2. a `check` case expecting a code the compiler does not report
3. a `check` case reporting a code no expectation names — the D-237 rule
4. a `loopback` case that leaves a socket open at exit (D-151 should trap it,
   and the harness should report the trap rather than the exit code)
5. a `// expect-signal: 13` case whose program exits normally
6. a `parse` case that does not parse
7. a tree check fed a deliberate violation — **a `sendto` call site without
   `MSG_NOSIGNAL`**, which must be caught by `check_msg_nosignal`

**Rule:** the self-check runs **first** in every full invocation, and case 7 is
the one that proves this library's headline rule is actually enforced rather
than merely stated.
