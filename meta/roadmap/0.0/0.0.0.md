# 0.0.0 — the language probes — PLANNED (the execution record is appended as steps land)

> **Scope:** twelve small Nitpick programs that ask the compiler whether the
> shapes `meta/specs/` depends on are spellable, compilable and correct. No
> library code is written in this subcycle. What it produces is **a verdict per
> probe** and, where a verdict is negative, an amended specification and a
> recorded decision.
>
> **Why first, and why these twelve.** `meta/specs/` was written against the
> compiler's documentation *and against its source*, and the compiler project's
> own most expensive finding is that *a construct that parses is not a
> construct that works*. Three of these probes are not reassurance —
> **04 (`SIGPIPE`), 09 and 10 (the `OwnedFd` asymmetry)** — they are the
> experimental basis of `SK-013` and `SK-035`, which between them decide every
> send in the library and the entire server model. Both facts were read out of
> `runtime/npkrt.ll` and `src/frontend/` rather than executed. This subcycle
> executes them.

---

## 1. Where you are

- Nothing is built. `src/` holds directories with README files.
- The compiler is at `../../nitpick`, cycle 1.5 (verification), self-hosting
  declared under D-202. Build it per its `CLAUDE.md`; the artifact these probes
  use is `build/npkc` from `npkg build`, or `.internal/quickemit/npkc` from
  `quickemit.py`, whichever is current.
- There is no `nsockets` harness yet. **Probes are run by hand**, one command
  each, and that is deliberate: the harness is 0.0.2, and building it against
  an unverified set of language assumptions is the mistake this subcycle exists
  to avoid.
- The probes live in `tests/probe/` and **stay in the tree permanently**. They
  are a regression suite for the language and kernel facts this library depends
  on, and 0.0.2 picks them up as ordinary stage entries.

---

## 2. The command

For each probe, from the `nsockets` tree root, with `NPKC` pointing at the
built compiler:

```
$NPKC tests/probe/NN_name.npk -o /tmp/p.ll \
  && llc -O0 -filetype=obj -relocation-model=static /tmp/p.ll -o /tmp/p.o \
  && ld.lld -static /tmp/p.o ../../nitpick/build/npkrt.o -o /tmp/p \
  && /tmp/p ; echo "exit $?"
```

A probe **expected to be refused** stops at the first command, and its verdict
is the diagnostic code and span, recorded verbatim.

**Every probe exits 0 on success and a distinct positive code per assertion it
fails**, so a failure names itself. `exit 0` additionally asserts, through
D-151 and D-188, that nothing leaked — which for a socket probe means every
descriptor was closed.

Probe 04 is the exception: **one of its two legs is a program that must die of
a signal**, so it runs as a parent that forks a child and inspects the child's
wait status. §4 says how.

---

## 3. Decisions taken at planning

- **P-1 — a probe is a program, never a library file.** It has its own `main`
  and `failsafe` and imports nothing from `src/`. A probe that needed library
  code would be testing the library, which is what every other cycle is for.
- **P-2 — a refused probe is a *result*, not a failure of the subcycle.** Probe
  09 is expected to be refused and probe 10's second half is; their value is
  the exact diagnostic. The subcycle fails only if a verdict is *undecided* — a
  compiler crash, a hang, or an output nobody can read.
- **P-3 — the verdict is recorded before the next probe is written.** A batch
  of twelve written and then run together is a batch where the fourth one's
  answer would have changed the fifth one's design.
- **P-4 — a negative verdict amends `meta/specs/` in the same commit.** Not a
  note to self, not a TODO. The specification is the authority (`SK-002`) and
  an authority known to be wrong and not corrected is worse than none.
- **P-5 — every probe uses `socketpair` or loopback with port 0.** No external
  host, no privilege, no fixed port. A probe that needs the network is a probe
  that cannot be run in CI, and there is nothing in this set that needs one.
- **P-6 — the probes stay.** They become 0.0.2's first stage entries, so a
  compiler or kernel change that breaks one of these facts is caught by
  `nsockets`' own harness rather than by a server misbehaving in 0.8.

## 4. The probes

Each entry: **what it asks**, **why it matters**, and **what a negative verdict
costs**.

### 01 — `socket`, `socketpair`, and the atomic flags

**Asks:** `sys(41, AF_INET, SOCK_STREAM|SOCK_NONBLOCK|SOCK_CLOEXEC,
IPPROTO_TCP)`; then `sys(53, AF_UNIX, SOCK_STREAM|…, 0, sv)` with an 8-byte
`wild` block for the two descriptors. Assert both are ≥ 3, that
`fcntl(F_GETFL)` reports `O_NONBLOCK`, and that `fcntl(F_GETFD)` reports
`FD_CLOEXEC`.

**Matters because** `SK-012` puts every socket on this path and never on a
follow-up `fcntl`. It is also the first `sys` call with a pointer argument in
this library, so it exercises D-192's trampoline.

**A negative verdict costs** the atomic-creation rule, and the fallback —
`socket` then two `fcntl`s — reopens the `execve` window `SK-012` closes.

### 02 — `sockaddr` layouts, through the kernel

**Asks:** lay out `sockaddr_in` in a 64-byte `buffer` with a sentinel byte at
offset 16; `bind` a loopback socket to port 0; `getsockname` it back; assert
family 2, a non-zero port, address `127.0.0.1`, and **the sentinel untouched**.
Repeat for `sockaddr_in6` (sentinel at 28) and for `sockaddr_un` with an
abstract name (sentinel past `2 + 1 + len`).

**Matters because** `SK-016` is the rule that every layout is measured and
asserted by a running program, and this is that program. The `ntui` analogue
(kernel `termios` 36 bytes, glibc's 60) is the shape of the bug it prevents.

**A negative verdict** means a layout table in `ADDRESS_MODEL.md` §2 is wrong,
and the kernel wins.

### 03 — `msghdr`, `iovec`, `cmsghdr`, `ucred`

**Asks:** `#size_of` assertions for the Nitpick structs mirroring each (56, 16,
16, 12); a `sendmsg`/`recvmsg` round trip over a `socketpair` carrying one
`iovec` and **no** control payload; assert the bytes and that `msg_flags` came
back zero.

**Matters because** the `msghdr` layout is `ANCILLARY_MODEL.md`'s foundation
and the compiler's own Bridge already depends on exactly these numbers — this
probe confirms them independently rather than trusting a read of that file.

### 04 — **`SIGPIPE`** — the load-bearing one

**Asks**, in two legs:

1. `fork`-shape a child through the floor's `clone_exec`, or simply run the
   probe twice with an `// argv:` token selecting the leg. In the child: make a
   `socketpair`, close one end, and `sendto` on the other **with a flags word
   of 0**. **Assert the child dies of signal 13.**
2. In the parent: the same, `sendto` with `MSG_NOSIGNAL` (`16384`). **Assert
   the call returns `EPIPE` (`-32`) in `Result.err` and the process survives.**

**Matters because** it is the experimental basis of `SK-013`, which governs
every send in this library. The claim — that the Nitpick runtime installs no
`SIGPIPE` disposition, so the default (terminate) is live — was established by
reading `runtime/npkrt.ll` and by the compiler's own comment in
`lib/nbridge.npk`. **This runs it.**

**What each verdict means:**

| Leg 1 | Leg 2 | Reading |
|---|---|---|
| dies of 13 | `EPIPE` | as specified. `SK-013` is load-bearing. |
| survives | `EPIPE` | something ignores `SIGPIPE` — the runtime, or the executor. `SK-013` becomes belt-and-braces. **Record it, keep the rule** (it costs nothing and the next runtime may not), and amend `SAFETY.md` §2's claim to say what is actually true. |
| dies of 13 | dies of 13 | `MSG_NOSIGNAL` is not reaching the kernel. A `sys` argument-marshalling bug, and everything stops until it is found. |

**Run this probe first.**

### 05 — `OwnedFd`'s drop is the close

**Asks:** `own_fd` a socket inside a block; at the closing brace, assert the
descriptor number is no longer open (a `fcntl(F_GETFD)` returning `EBADF`).
Then `release_fd(move o)` and an explicit `close`, asserting the verdict is
observable and that a second close reports `EBADF`.

**Matters because** `SK-011` makes the drop the whole lifetime story and there
is no `close` in the surface.

### 06 — `Reader` / `Writer` over a struct holding an `OwnedFd`

**Asks:** a struct with one `OwnedFd` field implementing the **prelude's**
`Reader` and `Writer` — `Self->` receiver, `async`, the trait's exact
signature — driven through a generic bound and, separately, through
`dyn Writer`. The `write` body uses `sendto` with `MSG_NOSIGNAL`, **not** the
floor's `write` (`SK-013`'s corollary).

**Matters because** `SK-027` is the library's headline interoperability
property, and TYPE-048 requires an impl to keep its trait's `async`. The `dyn`
leg is the one to watch: object safety admits `async` with a `Self->` receiver
since D-185, and it needs the frame-size tail.

**A negative verdict on the `dyn` leg costs nothing** — the library's own
surface is generic — but it constrains what a consumer can do, and is recorded.

### 07 — `io_ready` and `io_ready2` on sockets

**Asks:** `io_ready(descr, 1, within)` (EPOLLIN) on the read end of a
`socketpair` with data pending — returns promptly; the same with no data and a
short deadline — returns `DeadlineExceeded`; `io_ready(descr, 4, within)`
(EPOLLOUT) on a writable socket; `io_ready2` over both ends with only one
ready.

**Matters because** every wait in the library is one of these
(`CONCURRENCY_MODEL.md` §1), and `io_ready2` is what makes fan-in expressible
without a `select` the language does not have.

### 08 — `connect`'s `EINPROGRESS` path, including the failure leg

**Asks:** a non-blocking `connect` to a **closed** port on `127.0.0.1`. Assert:
the call returns `EINPROGRESS` (`-115`) *or* fails immediately; `io_ready` for
`EPOLLOUT` returns; `getsockopt(SOL_SOCKET, SO_ERROR)` yields `ECONNREFUSED`
(`111`); and **a second `SO_ERROR` read yields 0**. Then the success leg
against a listener bound to port 0 in the same program.

**Matters because** `SK-014` is written entirely around this sequence, and the
two facts that make it necessary — writability on failure, and the read
clearing the error — are exactly what this asserts.

**Note the loopback caveat**: a loopback connect often completes immediately
and never returns `EINPROGRESS`, which is why the *failure* leg is the one that
exercises the interesting path. Both legs are required.

### 09 — **an `OwnedFd` as a channel element** — expected REFUSED

**Asks:** `Channel<OwnedFd, 0, 4>` and, separately, `Channel<Sockish, 0, 4>`
where `struct:Sockish = { OwnedFd:descr; uint8:family; }`. **Both expected
refused**, `NITPICK-TYPE-057`.

**Matters because** it is half of `SK-035`. The refusal was read out of
`chan_elem_verdict_recorded` (`TY_OWNEDFD` → `CHAN_ELEM_FD`) and
`type_contains_borrow_recorded` (`TY_OWNEDFD` → `true`, so a struct holding one
refuses transitively). **Record both diagnostics verbatim**, including whether
the struct case names the field.

**If either is ACCEPTED**, `SK-035` is wrong in a way that *widens* the design
space — a worker-pool server would become expressible — and that is a decision
to reopen rather than a failure.

### 10 — **an `OwnedFd` moved into a spawn** — expected ACCEPTED

**Asks**, as a pair with 09:

1. `drop handler(move(o));` where `handler` is `async func:handler =
   NIL(move OwnedFd:o)`. **Expected accepted.**
2. `drop handler2(@o);` — a **borrow** across the spawn. **Expected refused**,
   D-004 rule 4 as narrowed by D-180.

**Matters because** it is the other half of `SK-035`, and the *asymmetry*
between 09 and 10 is the whole finding. The move's legality was read out of
`type_holds_pointer` in `escape.npk` (`TY_OWNEDFD` → `false`, "a descriptor
NUMBER"); `IO_REFERENCE.md` §6 states it in prose.

**If leg 1 is REFUSED**, the accept-then-spawn model is not expressible either,
which would leave only "handle connections inline, one at a time" — and the
library's server story would have to be re-planned from scratch. **This is the
single most expensive negative verdict available in the set**, which is why it
is run early and as a pair.

### 11 — `SCM_RIGHTS` over a `socketpair`

**Asks:** open a file, pass its descriptor over a `socketpair` with `sendmsg`
carrying one payload byte and a `cmsghdr` of `SOL_SOCKET`/`SCM_RIGHTS`;
`recvmsg` with `MSG_CMSG_CLOEXEC` (`0x40000000`); assert the received
descriptor is a *different number*, that reading through it gives the file's
bytes, and that `fcntl(F_GETFD)` reports `FD_CLOEXEC` set.

**Matters because** it is `ANCILLARY_MODEL.md` end to end, it asserts `CMSG_LEN`
(20) against `CMSG_SPACE` (24) — N-2's distinction — and it confirms
`MSG_CMSG_CLOEXEC` actually reaches the kernel through `sys`'s flags word.

### 12 — a POD address array

**Asks:** a `Vec`-shaped array of 4 096 `SocketAddr`-shaped POD values (a tagged
enum over a 20-byte and a 6-byte payload): fill, read back, copy the whole
array, clear. Assert `#size_of` for the enum and for `UnixAddr`
(`uint8[108]` + two bytes).

**Matters because** `SK-022` says every address type has no owning field
precisely so this works, and because a `#size_of` surprise here changes
`ADDRESS_MODEL.md` §1's declarations.

## 5. The steps

Each step is one commit.

**Step 1 — the three that decide the design: 04, 09, 10.** Run them, record
verdicts, and if any contradicts its specification, **stop and re-plan** before
writing another probe. Order within the three: 04 first (it is the cheapest to
run and the most consequential to the send path), then 09 and 10 as a pair.

**Step 2 — the kernel-layout probes: 01, 02, 03.** These confirm the numbers
every spec table states.

**Step 3 — the language-shape probes: 05, 06, 12.**

**Step 4 — the behavioural probes: 07, 08, 11.**

**Step 5 — the record and the amendments.** Every verdict into §7; every
consequence into `meta/specs/` and `meta/DECISIONS.md`;
`tests/probe/README.md` written, saying what the directory is for and that a
probe is never deleted.

## 6. What the executor should know

- **The reserved words will bite immediately.** `fd`, `raw`, `in`, `any`,
  `buffer`, `move`, `end`, `limit`, `error`, `on` — `specs/BUILD.md` §7 is the
  list, and §7's second half names the substitutes (`descr`, `wire`, `sock`,
  `hi`, `cap`).
- **`discard(x);` takes parentheses. `defer { … }` takes no trailing
  semicolon.** Declarations end `};`; control-flow blocks do not.
- **Adjacent string literals do not concatenate.**
- **A file's `mod:` name must equal its basename**, or the loader reports
  `NITPICK-RESOLVE-005` at line 1 and says nothing about the name.
- **`raw` is licensed only on a `never fails` callee** (D-163). An `async`
  callee is never `never fails`, so `raw await f()` is unspellable; use
  `relay await`, `await … ?| d`, or `await … ?! E`.
- **`sys` takes at most six register arguments after the number** and every one
  must fit a register; a pointer becomes a number at the trampoline (D-192). A
  nested bare-builtin call as an argument is refused — bind it to a typed name
  first.
- **A `failsafe` must name every reachable error** (REACH-002), including the
  system ones. Copy the arm set from
  `../../nitpick/tests/backend/programs/proc_tool.npk` and prune.
- **Exit 0 means "and nothing leaked"** (D-151, D-188). Every probe closes every
  descriptor and frees every `wild` block on every path.
- **Bind to port 0 and read the port back.** No probe hardcodes a port.
- **Use the abstract namespace for `AF_UNIX`.** Nothing to unlink, nothing left
  behind, and no collision between two runs.
- **`llc` and `ld.lld` must be the pinned 20.1.2.** `llvm-config --version`.
