### 1.6 One module per root, and what a module compiled alone names

A root importing a module that defines `helper_twice`: the root's emission DEFINES that function, and linked as its
one object and `npkrt.o` the program exits 42. A module compiled alone names `npk_failsafe` when it holds an `async`
function — its scope join traps through its program's `failsafe` at its deadline — and not when its one function is
`never fails`, or can trap only on an addition. A module of the library's own shapes — a wait through `io_ready`, a
spawn that moves an `OwnedFd` in, a held `OwnedFd`, a `sys` call — compiled alone has 61 call edges the floor program
does not, to 20 runtime symbols, 13 of them the library's and 7 the floor's, and to `npk_failsafe`; the scan flags
none. Its scope joins call `npk_thread_join`, as `io_ready`'s does. And a module that makes a `Mutex` and never holds
it has three call edges the floor program does not, to `npk_alloc_managed`, `npk_chain_push` and `npk_raise`, each the
floor's: no call-edge scan can see that lock, where a held one calls a guard's release, which the scan denies (block
4m's `lock-in-library`).
